# 栏目设计落地方案

状态：实现前规划；本文件不代表页面已经完成。

依据：当前首页基础规范、栏目再次评估记录，以及分享对话 https://chatgpt.com/share/6aa2a821-bb1c-83ec-a6bd-751ef951f4b7 中读取到的文字和图片生成说明。分享快照结束于关于页图片生成，未读取到用户所说的最终总结；原图未成功显示，不能据此声称像素级还原。

## 1. 保留的基线

- 首页前两屏的整体比例、插画和个人表达延续当前版本。
- 首屏三张统计卡独立，按钮在统计之前；当前项目卡不跳转；保留“想与做的书桌”铭牌。
- 导航计划调整为：首页 / 项目 / 知识 / 思考 / 资源 / 关于。
- 新栏目继承 home-foundations.css 的容器、边距、字号、颜色与按钮规则。全站正文容器最大 1216px，不新增竞争的全局宽度。
- 普通栏目页和正文高度由内容决定，不强制每个栏目占满一个屏幕。
- 设计图中的项目数、篇数、版本、日期、成果与联系信息不能直接发布为真实数据。

## 2. 页面清单与建议路由

以下为建议的公开地址；迁移时保留旧 ID、查询参数和详情链接。

| 页面 | 建议地址 | 内容与布局 |
| --- | --- | --- |
| 项目列表 | #/projects | 栏目介绍、项目阶段筛选、项目卡片 |
| 项目详情 | #/projects/:id | 简介与封面、当前阶段、问题、方案、决策、过程、验证与复盘 |
| 知识入口 | #/knowledge | 搜索、主题筛选、知识条目与系列入口；搜索时直接展示结果 |
| 知识详情 | #/knowledge/:id | 一句话理解、解释、例子、个人理解与关联内容，按实际材料展示 |
| 系列目录 | #/series/:id | 简介、有序章节、关联项目与资源；章节引用现有内容 |
| 思考列表 | #/thinking | 栏目介绍、可选精选、时间列表、搜索与类型筛选 |
| 思考详情 | #/thinking/:id | 标题、摘要、日期、正文、可选目录、关联阅读 |
| 资源入口 | #/resources | 搜索、类型筛选、资源卡片，独立标注来源与使用状态 |

不单独新增“所有知识”页面；先由知识入口承载搜索和浏览。不为三张关于效果图创建三个重复页面。关于图中的内容合并成同页区段，重复内容取舍后使用。

## 3. 内容迁移

| 当前内容 | 目标 | 注意事项 |
| --- | --- | --- |
| topics | 知识 | 保留稳定 ID、知识关联与发布状态 |
| notes 的笔记、成长记录 | 思考 | 允许短内容，不强制写成长文章 |
| learning 聚合 | 新入口拆分 | 旧 learning 链接先保留兼容入口，不直接丢弃原筛选含义 |
| work | 项目 | 先使用已公开的 learning-site 项目 |
| toolbox | 资源 | 保留 Prompt 复制、清单操作、插件访问等现有功能 |
| library、reading | 逐条判断 | 外链资料进入资源，个人分析进入思考；先核实标题与来源 |
| collections | 系列或专题 | 保留有序引用，不复制正文，不将实践专题伪装成完整课程 |
| saved | 访客收藏 | 与作者公开的资源库保持不同数据含义 |

旧 work、topics、notes、toolbox、library 等链接继续可访问。路由迁移应一起检查导航选中态、搜索结果、相关链接、收藏链接、页面标题与浏览器前进后退。

## 4. 第一批：项目栏目

### 项目列表

顶部使用小标签“项目 / Projects”、栏目标题和短介绍。下方展示真实项目列表。只有一个公开项目时，采用一张横向重点卡：左侧项目封面或真实页面预览，右侧标题、摘要、阶段和详情入口。增加项目后再转为规则网格，不留两个虚假占位案例。

阶段或类型只有在能帮助筛选时展示；统计从公开数据计算。项目列表卡可进入详情，与首页首屏不跳转的当前项目卡是不同组件。

### 项目详情

先使用“想与做 · 个人学习网站”，保留 ID learning-site。页面顺序：

1. 面包屑、项目标题、摘要、真实阶段、封面。
2. 为什么做：学习材料零散，内容新增被页面调整打断。
3. 当前做到了哪里：只陈述现有代码与记录能确认的状态。
4. 方案与关键决策：个人首页、内容引用、按类型展示。
5. 设计与实现过程：有对应截图或记录再展示。
6. 验证与阶段结果：区分已做检查与未来计划。
7. 相关知识、思考与资源。

没有材料的章节不渲染空卡片。GitHub、在线体验等按钮只在真实 URL 可用时出现。“查看完整过程”若指向同页章节，则用锚点，不制造重复详情页。

## 5. 组件与排版

- 全站共用：导航、栏目标题、面包屑、主次按钮、搜索框、筛选标签、状态标记、空结果、关联内容。
- 列表分型：项目封面卡、知识条目卡、思考列表项、资源卡、系列章节行。
- 正文共用：H1/H2/H3、段落、列表、图片及说明、引用、提示块、代码与对比表。
- 正文阅读宽度建议 680–760px；外层仍使用 1216px。宽屏允许目录侧栏，中屏优先保证正文宽度，手机将目录折叠到正文前。
- 知识和思考效果图中的三栏结构按可用宽度启用，不在平板硬塞三个窄栏。
- 内容类型和主题分别筛选；“开源”“常用”“外部来源”不能混进同一互斥类型组。
- 所有页面支持现有明暗主题、键盘聚焦和移动端布局。

## 6. 数据与模板边界

延续当前模块，不为视觉升级更换框架。复用现有详情渲染、安全链接处理、发布过滤和关联结构。

基础字段：id、title、summary、publication、date/updated、tags、related。项目增加阶段与可选封面；资源独立管理类型、来源与访问方式。正文优先使用现有字段，出现真实的图文混排需求时再增加可选内容块，不一次迁移所有旧数据。

新增内容的工作流：确认主要归属 → 填入数据与素材 → 选择栏目模板 → 自动生成列表、详情和相关入口 → 检查发布状态、链接、正文与小屏表现。遇到新内容形式时增加模块，不修改全站基础宽度。

## 7. 实施与验收顺序

1. 盘点数据、确认来源、实现新旧路由兼容与新导航。
2. 项目列表与一个真实项目详情，验证首个栏目模板。
3. 知识与思考入口、正文目录与系列。
4. 资源与关于，同步首页入口和下方摘要区。

每批验证：相关测试、旧链接、搜索筛选、无结果状态、前进后退、发布过滤、键盘操作、浅深色和移动端；代表宽度使用 1435、934、768、390、320px。检查容器对齐、长标题换行、横向溢出与按钮触控尺寸。

## 8. 素材需求

当前数据足以做项目栏目结构和 learning-site 示例。正式视觉对照仍需要分享中的原始设计图及最后总结。其他项目需补充真实介绍、阶段、封面、过程与结果；关于页联系方式仅使用用户提供的值。缺失的材料不阻止先做已确认内容，也不通过编造补齐。
