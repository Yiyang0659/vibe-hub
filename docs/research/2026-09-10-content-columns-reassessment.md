# 栏目与长期内容规划：再次评估

日期：2026-09-10。状态：根据用户新说明整理的建议，尚未批准实施。本轮不修改页面或迁移内容；已完成的首期实现保持现状。

## 1. 建议导航与任务边界

建议：首页 / 项目 / 知识 / 思考 / 资源 / 关于。

不是因为六个栏目一定优于五个，而是用户现在明确存在“查找知识、阅读个人记录、获取可用资源”三种不同任务，值得分别提供入口。

| 栏目 | 主要任务 | 内容范围 |
| --- | --- | --- |
| 项目 | 了解自己做了什么、如何推进 | 独立实践、产品、原型、插件、Skill、脚本；阶段、问题、验证和复盘 |
| 知识 | 查懂一个概念或学会一种方法 | 术语、原理、教程、可重复使用的方法说明；以主题或系列组织 |
| 思考 | 了解一次具体的理解、观察、分析或判断 | 短笔记、长文、阅读心得、产品拆解、竞品分析、复盘、成长记录 |
| 资源 | 找到并使用值得保留的东西 | 工具、插件、Skills、Prompt、模板、网站、资料及外部项目入口 |
| 关于 | 了解作者与建站动机 | 简介、当前关注、正在做什么、网站缘起与可选联系方式 |

首页是精选入口，不是额外内容库。栏目划分首先按条目的主要用途，作者身份和篇幅不决定归属。

## 2. 附件分析中合理与需要修正的部分

合理：学习栏目拆出知识与个人记录；资源比工具涵盖面更合适；项目保留过程与复盘；通过关联链接避免栏目孤立；关于保持简单。

需要修正：

1. 知识不能严格定义成客观输入、思考不能严格定义成主观输出。自己的知识整理也有判断，竞品分析也需要事实。区别是长期可查的解释与围绕具体情境的记录。
2. 项目不设“足够完整/足够大”的门槛。明确目标、范围和实际推进即可记录进行中实践；小脚本也可能形成独立项目，复杂外部产品也不是自己的项目。
3. 思考允许观察、疑问与阶段认识，不强迫每篇都给出成熟结论。文章只是篇幅与表达形式，不作为新的互斥内容类别。
4. 系列是内容之间的组织关系，不应与知识点作为同层原子类型。系列有主题、说明和有序引用，章节正文维护一份；主入口按系列整体用途决定。
5. AI、Agent、开发、Web、Workflow 不适合全部作为并列主主题；工具、网站、开源也不是互斥类型。主题、类型、来源、使用状态分别管理。
6. 首页不必为每栏安排一整屏，也不需要为了支撑模板先造完整课程。
7. 附件提及的“滑一叠”“内容系统 Agent”等项目没有在本次任务中核实，不能作为用户已完成项目直接发布。

## 3. 最容易混淆的情况

| 内容 | 默认归属 | 判断依据 |
| --- | --- | --- |
| MVP 是什么、怎样识别核心假设 | 知识 | 可重复查阅的解释 |
| 这次我为什么收缩网站范围 | 思考 | 具体经历与判断 |
| 本站的范围、阶段、实现和结果 | 项目 | 一项实践的完整入口 |
| 一份可复制的范围检查清单 | 资源 | 直接使用 |
| 某个网站的链接与收藏理由 | 资源 | 访问入口 |
| 网站导航、页面结构怎么设计 | 知识 | 通用解释或方法 |
| 对某个网站的信息架构分析 | 思考 | 针对对象的分析 |
| 收藏一篇外部学习文章 | 资源 | 保存来源和阅读入口 |
| 将资料整理成自己的原理说明 | 知识 | 独立解释，并关联来源 |
| 阅读之后形成的不同意见 | 思考 | 个人判断，并区分事实与推断 |

同一材料可以支持多篇不同用途的内容，但不是要求一份材料必定拆成多篇。只有内容各自有独立价值时再分开；每篇有一个主要归属，其他栏目通过引用呈现。

## 4. 栏目内部组织建议

- 项目：按进行中/已完成/暂停等阶段辅助浏览。详情默认包含目标、当前阶段、关键过程、观察结果；决策、验证、问题和复盘按材料增加。深入复盘可以单独成为思考，项目页放摘要与链接。
- 知识：初期主题可用 AI、产品、开发、设计；Agent、Web、评测等先作为更具体的标签。必要时类型区分概念与指南；系列单独提供目录入口。领域映射需要对应现有数据后再定，不在本轮直接修改。
- 思考：默认时间列表，初期类型只需笔记、分析、复盘；产品拆解、竞品分析是分析的细分标签，成长记录可以作为复盘/笔记展示。没有内容的分类不露出。
- 资源：类型可用工具/插件、Skill、Prompt/模板、网站/资料。来源另标原创/外部/改编；使用状态可选常用/试用/待探索。“开源”是属性，GitHub 是来源平台，不单独与工具类型并列。仅收藏过不显示为常用。
- 关于：为什么做这里、现在在学/做什么、简短介绍及联系，不增加必须填写的长履历。

栏目名称比较：思考与品牌“想与做”契合，可用“笔记、分析与复盘”说明它也允许短记录；若个人感觉思考一词增加写作压力，可用“记录”，结构不变。资源是最清楚的主导航名字；“百宝箱”更有个人感但可预期性较弱，“收藏”容易与访客本地收藏混淆。建议暂用资源。

## 5. 项目与资源怎样共存

自制插件的项目页保存开发过程、问题、阶段与结果；资源区可提供用途、使用方式和获取入口，并关联项目。不要复制两份长介绍或两份更新记录。

DeepSeek Harness Sync 当前已有工具说明，适合先保留为资源。用户补充开发过程后，可以建立对应项目案例；不根据仓库存在就编写未经提供的成效或开发经历。

资源库是作者整理并公开的推荐内容；“已保存”是当前访客在浏览器里的个人收藏，两者不能合并成同一份清单。

## 6. 对当前项目的具体影响

| 当前模块或内容 | 新方案中的位置 |
| --- | --- |
| topics 及现有知识详情 | 知识，保留数据与原链接 |
| notes 的两篇建站笔记与成长记录 | 思考 |
| learning 聚合页 | 拆分知识与思考入口，旧链接提供兼容导航 |
| collections 专题 | 保留引用结构；按用途确定知识系列或实践专题入口 |
| work | 项目，延续现有轻量详情 |
| toolbox 与 library | 从资源入口聚合，原类型功能和旧链接保留 |
| reading | 按内容用途归类：外部资料入口进资源，原理说明进知识，个人阅读分析进思考；逐条判断 |
| saved | 继续作为个人收藏功能 |
| about | 保持简洁介绍 |

当前“用 AI 搭建自己的学习网站”专题包含建站动机与概念，属于实践专题，不能仅改名就当成完整教学路线。

当前资料数据也需要核对：`library/data.js` 中有条目标题同时包含 VibeHub 与 MDN，而 URL 指向 MDN。后续迁移应先确认具体对象与来源，再统一资源展示，不能机械搬运。

## 7. 首页与实施顺序

首页继续沿用现有视觉。前两屏介绍个人与网站；后面使用最近思考、知识/专题、正在做的项目、精选资源的摘要区，有内容才出现。顺序随当前积累调整，不固定每栏整屏。

下一次实施前：先确认主要归属规则；逐条盘点现有数据及来源；确定知识、思考、资源的新入口与旧链接兼容；最后调整首页和筛选。现有模板、稳定 ID、关联结构与设计变量可以复用，不需要整体重建。
