# 想与做：个人展示与学习记录整合方案

日期：2026-09-10。状态：用户已确认并授权实施；首期页面与内容模板已落地。

依据：用户此前明确的学习记录定位，以及本轮提供的“个人作品展示 × 学习知识系统”文本。该文本中的项目名称、经历、量化结果和课程章节数量均不作为用户已完成内容的证据。

## 1. 定位与方案关系

定位建议：记录自己如何学习 AI、理解问题、动手实践，再把经验整理成可以再次使用的知识与工具。

首页呈现个人身份和当前关注，学习栏目承载知识形成过程，项目展示实际尝试，工具承载复用产物。保持现有个人网站视觉，不要求先拥有丰富项目或成熟长文。

本方案优先于上一轮“首页 / 知识 / 笔记 / 工具 / 关于”的建议：保留项目主入口，建议将“文章”改为“学习”，在栏目内部组织多种学习内容。旧版页面模板研究继续作为视觉与组件参考。

知识、实践和工具之间可以建立关联，但不要求每条知识都已有项目应用，也不要求每次学习都产出工具。当前目标是降低记录和回看的成本。

## 2. 建议的信息架构

```text
首页
项目
  项目与小实验列表
  实践详情：目标、过程、验证与复盘
学习
  学习总览
  主题与专题（积累后组织为路线）
  知识条目：术语、概念、区别
  学习笔记：问题、尝试、理解与复盘
  成长记录：按时间记录理解的变化
工具
  插件、脚本、提示词、模板与清单
  工具详情：用途、使用方法、获取入口与限制
关于
  建站原因、当前关注、个人介绍与联系
```

以上是内容层级，不要求为每个节点立即开发独立页面。初期主题作为筛选，成长记录作为笔记类型，避免建立空页面。成熟专题出现后再增加路线页。学习总览连接现有术语与笔记内容，不通过改名把现有数据混为一种实体。

## 3. 首页展示

保留已确认的首页宽度、字体、色彩、插画及前两屏布局，针对新定位讨论文案、入口与后续模块。

| 区域 | 作用 | 当前建议 |
| --- | --- | --- |
| 首屏 | 认识作者与当前方向 | 保留“把 AI 想明白，也把它做出来”；主按钮建议“浏览学习记录”，次按钮“看看我的实践”；统计只计算真实已发布内容 |
| 关于这里 | 解释为何记录、可以看什么 | 保留现有第二屏；引导到学习、实践、工具 |
| 正在学习 | 明确当前关注 | 展示 1 个有真实记录的主题及其关联内容，无内容时不出现 |
| 最近记录 | 发现新的理解与尝试 | 混合展示知识条目和笔记，标明类型与日期，最多约 4–6 条 |
| 小工具与实践 | 看已有产物 | 初期合并成一个紧凑区域，工具和项目各自链接详情；内容多后再拆分 |
| 最近变化 | 体现积累过程 | 有真实成长记录时展示 1 条摘要；无内容时隐藏，不单独维持空时间线 |
| 页脚 | 次级入口 | 关于、联系、站点更新等按实际需要出现 |

后期项目较丰富时，可将实践区提前、单独展示精选案例。首页内容顺序不等同于内容关系顺序，不必复制“学习到工具”的每一步为整屏。

现有首页项目数为零时显示 03 的兜底值应在后续实施时移除；数据中的成果和数字需用户核对后再作为个人经历发布。

## 4. 栏目与详情展示规则

| 页面 | 列表或总览 | 详情 |
| --- | --- | --- |
| 学习 | 搜索、主题筛选、最近记录；知识与笔记有类型标识；有成熟专题时展示专题入口 | 使用知识或笔记各自模板 |
| 知识 | 紧凑索引，名称与一句话解释；不要求封面 | 概念、我的理解、具体例子；来源、误区、相关实践按需显示 |
| 笔记 | 日期、标题、摘要；默认按时间排列，无封面也成立 | 问题、理解或尝试过程、当前结论；按需插入图片、代码、待验证问题 |
| 专题／路线 | 目标、适用范围和现有记录；有明确顺序时才称路线 | 简介、章节目录、关联知识与实践；未写章节留在私人计划，不伪装成已发布内容 |
| 项目与实验 | 项目状态、简要目标、可选截图；单条也自然呈现 | 为什么做、做了什么、怎样验证、目前结果、复盘；可选目录和链接，不要求独立 Case Study 内容副本 |
| 工具 | 类型、用途、状态；插件与提示词使用不同类型 | 通用概览；插件显示使用/获取方法，模板显示正文/复制入口，清单显示可勾选项；实际入口依内容提供 |
| 关于 | 单页阅读 | 为什么建站、当前关注、自己的介绍、联系；不要求复杂履历或能力评分 |
| 成长记录 | 笔记中的一种类型，简洁时间列表 | 原来的理解、触发变化的事情、现在的理解、相关记录；可短至一段 |

成长记录承载真实认知变化；网站更新记录承载功能或内容更新。两者可以互相链接，不强迫把每次修复都包装成成长故事。

## 5. 内容填写模板

### 知识条目

必填：标题、一句话理解、说明与一个能帮助理解的例子。例子可明确标注为说明性假设，不伪装成亲身经历。

选填：在哪里遇到、容易混淆什么、参考来源、相关笔记/项目。学习状态可区分初步理解和已实践，但不要暗示未经验证的正确性保证。

### 学习笔记

必填：标题、遇到的问题或学习动机、理解/尝试过程、目前结论。结论可以是尚未解决及观察所得。

选填：截图、代码、参考资料、下一步、关联知识。篇幅不设最低长文要求，也不强制填写尚未解决的问题。

### 工具或插件

必填：名称、解决的问题、使用方法、当前可用状态。已发布可用工具提供相应获取/访问/复制入口；未发布的工具可以先作为实践记录。

选填：输入输出示例、效果截图、适用环境、已知限制、相关知识。插件不强制提供 Prompt 或 Checklist。

### 项目或小实验

必填：想解决的问题、实际尝试、当前状态与观察结果。

选填：实现过程、截图/仓库/演示、验证方法与证据、取舍和复盘。进行中允许尚无最终结果；验证可采用步骤与现象，不强制量化数字。

### 成长记录

记录一个真实变化：之前怎样理解，什么触发了变化，现在怎样理解。关联已有记录，避免重复写完整正文。

## 6. 第一批真实内容

先围绕一个已经在做的主题组织，例如“用 AI 搭建并维护自己的学习网站”。以下是候选数量和选题，不是必须完成的发布门槛。

| 内容 | 初始建议 | 候选材料 |
| --- | --- | --- |
| 主题 | 1 个 | 为现有记录加共同主题；初期不编造完整课程 |
| 知识 | 5 条左右 | 从实际接触的组件、路由、设计变量、本地存储、Git 中选择已经理解的概念 |
| 笔记 | 2–3 篇 | 为什么做本站；为何先确定模板再填内容；一次真实布局或实现问题的处理 |
| 工具 | 1 个 | 从用户已有小插件中选最常用的，整理用途、步骤和效果 |
| 实践 | 1 条 | 本站作为进行中的项目，只记录可核实的已完成部分 |
| 成长记录 | 1 条，可选 | 本轮从关注页面展示转向考虑长期内容积累的思考，由用户确认是否符合真实认识 |
| 关于 | 1 份简短介绍 | 建站动机、当前学习方向、希望如何使用这里 |

同一次实践可以产生多个内容，但内容职责不同。知识解释概念，笔记保留过程，项目汇总进展，工具给出复用入口；有实际关系时才链接。

## 7. 内容维护与组件原则

- 公共视觉继续继承已确认首页规范，阅读页按阅读任务控制正文宽度。
- 固定少量模板：内容索引/摘要、知识正文、笔记正文、实践详情、工具类型展示、关联内容、简洁时间记录。
- 每份内容有稳定 ID、类型、标题、主题、发布/更新日期和发布状态；正文按类型维护，可选字段为空时不渲染空标题。
- 首页精选、主题列表和关联区读取同一内容，避免复制正文。记录修订日期与首次发布日期，不用每次小修订刷新所有近期列表。
- 新增普通条目应只填数据与正文；定制交互演示才需要增加代码。
- 现有静态数据结构与渲染需要有针对性调整。当前必填未解问题、实验数字结果、工具 Prompt/Checklist 等规则尚未修改，不应把本方案当作现成发布格式。
- 先用真实的知识、笔记和插件各一份验证模板，再批量录入。当前不引入后台、登录、课程进度或题库工程。

## 8. 建议实施顺序

1. 核对现有数据，区分真实个人积累、外部引用、演示内容和待确认内容；暂不擅自删除。
2. 用已有材料试填知识、笔记、插件各一份，确认必填字段与展示效果。
3. 确认学习总览、知识/笔记详情、插件详情的模板，以及主导航从文章到学习的变化。
4. 调整相关校验、关联规则和自动列表，再调整首页展示权重与真实统计。
5. 补齐首批内容；专题积累足够并有合理顺序后，再做路线页面，练习继续留待实际需要。
