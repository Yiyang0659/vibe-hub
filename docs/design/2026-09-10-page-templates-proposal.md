日期：2026-09-10。状态：已归档的讨论稿，暂不实施；不是已确认规范。

目标：确定首页后续区域、项目、文章、工具、关于及详情页的展示方式，让日常新增内容通过既定模板自动呈现。

### 可选方向

1. **个人实践作品集 + 轻量阅读空间（推荐）**：首页精选，项目重图文，文章重阅读，工具重操作，关于重个人经历。与当前前两屏兼容。
2. **纯文字博客**：维护成本最低，文章最突出；项目和工具的展示力度较弱，也会大幅改变已确认首页的气质。
3. **资源门户 / 多功能工作台**：分类、搜索、功能入口丰富；首期内容少时容易出现空栏目，维护和信息组织成本更高。

推荐第一种。统一颜色、尺寸和交互，但根据读者任务使用不同内容组件。

## 2. 当前页面与目标的差异

已检查当前代码和本地浏览器：

- 首页前两屏已经确认，保留内容、插画、互动、三张独立统计卡和书桌铭牌。
- 首页后续已有项目、方法、文章和结尾区，但项目摘要重复问题与方案，卡片文字较重；各区目前依赖数组前几项。
- 项目、文章、工具内页仍有较大的宣传型标题、留白和统计区；栏目内容需要较长滚动才能进入视野。
- 文章页当前聚合思考、概念和阅读内容，不能在改版时无说明地删掉其入口。
- 关于页仍较偏能力证明和项目展示，需要与首页精选、项目栏目明确分工。

目标：首页负责建立印象和推荐，栏目页负责快速挑选，详情页负责深入阅读或使用。

## 3. 全站页面层级

```text
首页
├─ 项目栏目 → 项目详情 → 体验 / 源码（有链接时）
├─ 文章栏目 → 文章详情 → 相关项目 / 相关文章
├─ 工具栏目 → 工具详情 → 复制 / 下载 / 使用 / 外部打开
└─ 关于页面 → 代表项目 / 联系方式
```

五个主导航继续固定；分类与内容类型放在栏目内部。个人工作台、术语、阅读等现有能力保留兼容入口，不在本轮扩充为新的一级导航。

详情采用独立地址，不以弹窗承载完整长文。内部跳转同标签打开；明确标记的外部链接新标签打开。

## 4. 首页后续区块

建议顺序：已确认首屏 → 已确认第二屏 → 精选项目 → 近期文章 → 工具与方法 → 轻量联系与页脚。

第三屏及之后是自然高度的区块，不锁成每段100vh。

### 第三屏：精选项目

标题与一句说明在左，“全部项目”在右。主体采用一张横向重点卡（左图右文）+ 下方两张标准项目卡。

重点卡只呈现：封面、类型与状态、名称、一句摘要、查看案例。标准卡采用同一字段和交互，布局变为上图下文。首页最多展示3项，由精选字段和顺序控制，不由新增顺序偶然决定。

只有1项时仅呈现重点卡；2项时重点卡加一张标准卡，标准卡仍保持合理最大宽度；0项时隐藏整个区块，不输出空框。

### 第四屏：近期文章

显示3条横向文章摘要：日期/分类、标题、摘要、阅读时长、箭头。无封面也成立，不再为大编号单独分配一列。不在首页放筛选器或分页，“全部文章”进入栏目。

### 第五屏：工具与方法

显示3张紧凑卡：小图标、类型、名称、用途、查看工具。与项目卡明显不同：不依赖大封面，不在首页铺完整提示词或长清单。

### 收尾

用简短联系区域和统一页脚收束。已有第二屏承担自述，收尾不再添加一整屏自我介绍或重复大幅“从项目开始”行动区。

## 5. 项目栏目与详情

### 项目栏目：两列封面卡片

```text
共用导航
项目 / 一句栏目说明
类型筛选                              搜索
┌────────────┐  ┌────────────┐
│ 统一封面区   │  │ 统一封面区   │
│ 类型 · 状态  │  │ 类型 · 状态  │
│ 名称、摘要   │  │ 名称、摘要   │
│ 查看案例 →   │  │ 查看案例 →   │
└────────────┘  └────────────┘
分页（内容足够时）
共用页脚
```

- 桌面两列，窄屏单列；保持固定列宽上限，最后一项不突然放大。
- 类型、状态有文字标签；筛选只使用已有内容中的分类。
- 统一16:10媒体框。界面截图用 contain 完整显示，摄影类可按封面焦点 cover；缺图时使用站内统一的文字/图标封面。
- 名称最多展示两行，摘要最多三行；完整标题在详情中可见，不能只依靠鼠标悬停。
- 整卡默认进入案例，不因某项目有外链就悄悄改变整卡行为。体验与源码在详情头部明确提供。
- 默认精选在前，其余按公开日期倒序，使用稳定ID打破同日排序；页头与筛选区紧凑，桌面首个视口出现第一行项目。

### 项目详情：案例阅读模板

```text
返回项目
项目名称 / 摘要 / 类型 / 状态
角色、时间（有数据才显示）     [体验] [源码]
封面或演示媒体
正文阅读区                         章节目录
  小标题、段落、图片、图表
  步骤、对比、结果、引用
相关内容 / 下一项目
```

固定外壳与正文组件，不要求每个项目都填满相同数量的章节。完整项目可以有多个章节；小实验使用相同模板，只显示实际提供的内容。不显示空白“结果”“挑战”等栏目。

## 6. 文章栏目与详情

### 文章栏目：单列阅读列表

栏目标题和说明 → 搜索与分类 → 可选精选文章1条 → 普通文章列表 → 分页。

列表每条结构为“元信息—标题—摘要”，右侧可选小缩略图。无图时文字自然占用空间，首页与栏目复用同一条目组件。避免瀑布流，以保持日期顺序和扫读路径清晰。

当前思考、阅读和概念聚合可作为二级类型筛选保留；旧阅读与术语详情地址继续兼容。具体分类名称可在后续内容盘点时调整，不影响列表结构。

### 文章详情：阅读列 + 可折叠目录

- 标题、摘要、分类、发布日期、可选更新日期；阅读时长自动计算。
- 正文最大约760px，中文正文建议18px、行高约1.8；窄屏可为17px。它是文章阅读用途的规则，不覆盖首页已确认字号。
- 桌面右侧约200px目录，仅正文出现至少3个二级标题时显示；窄屏移到正文上方折叠。
- 正文不使用可见网格底纹；图表、图片可使用更宽的媒体区，文字仍保持阅读宽度。
- 通用正文能力：标题、段落、列表、引用、提示块、图片与说明、代码复制、表格、链接、视频。
- 阅读结束提供至多3项相关内容与返回文章入口；不堆叠大量推荐模块。
- 交互演示是按需模块。普通新增文章不需要写JavaScript；新的专用交互仍需要一次开发。

## 7. 工具栏目与详情

### 工具栏目：紧凑功能卡

栏目标题和说明 → 类型筛选与搜索 → 三列卡片（平板两列、手机一列）→ 分页。

卡片包含：小图标、名称、类型、一句用途、明确动作。类型决定详情操作区域，不改变外壳。

| 类型 | 详情主要呈现 | 主要操作 |
| --- | --- | --- |
| Prompt | 说明 + 模板代码框 + 示例 | 复制模板 |
| Checklist | 说明 + 可勾选列表 | 勾选、重置 |
| Template | 文件说明 + 预览 + 使用步骤 | 下载文件 |
| Workflow | 步骤、各步输入输出、示例 | 复制步骤或模板 |
| App / 外部工具 | 简介 + 使用入口 + 边界说明 | 打开工具 |

卡片是 article 容器，标题链接与复制按钮互不嵌套。不要在一个整卡链接内再嵌套按钮。

详情上方先出现可用内容及主要操作，补充说明放后面。复制成功有反馈，失败时可手动选取；下载仅在存在有效文件时显示；清单进度仅保存在本机，不伪装为跨设备同步。

已存在的工作流、Prompt、清单和模板通过这些类型映射，避免每次新增一种内容就写一个专用详情页面。

## 8. 关于页：个人介绍 + 近况 + 时间线

```text
共用导航
照片/插画              姓名、当前身份、简短介绍、联系
个人介绍与建站动机       近况卡
经历或学习路径时间线
关注方向（短条目）
少量代表实践链接
联系方式与页脚
```

照片、正文、近况在视觉上各有位置；手机按介绍—图片—近况—经历顺序重排。时间线自然展开，有数据再显示；不要求用虚构履历填满布局。代表实践控制在2项以内，使用紧凑链接复用已有项目数据。

## 9. 组件与规则怎样固定

### 三层约定

1. 基础规则：尺寸、字体、颜色、间距、圆角、边框、响应式、聚焦和悬停状态。
2. 内容组件：分区标题、项目卡、文章条目、工具卡、元信息、筛选搜索、分页、媒体框、正文块、目录、时间线、关联内容、空状态。
3. 页面模板：首页编排、项目索引、项目详情、文章索引、文章详情、工具索引、工具详情、关于。

同一种内容只维护一份记录。首页、栏目和详情读取同一记录；首页是否展示由精选配置决定。

### 既定规则与新增建议

| 项目 | 已确认基础 / 本轮建议 |
| --- | --- |
| 总容器 | 沿用最大1216px及已确认响应式边距 |
| 导航 | 沿用现有五个主栏目及最大1024px规则 |
| 主次按钮 | 沿用48px；导航最小点击范围44px |
| 颜色与插画 | 沿用浅灰白、蓝绿点缀、黑白线稿；主题沿用现有变量 |
| 栏目页标题 | 建议桌面40–48px、手机30–36px；紧凑页头，不再重复首页首屏体量 |
| 正文宽度 | 建议阅读列最大760px；宽媒体区约1000px以内；均受1216px外容器约束 |
| 卡片间距 | 建议统一24px；卡片内边距24–32px |
| 背景 | 网格仅用于页头和外侧留白；正文及信息面板保持实底 |
| 动效 | 轻量颜色/边框/位移反馈；减少动态偏好下取消非必要移动；内容不依赖动画完成才可读 |

### 自动化约定

- 新增内容只提供稳定ID、标题、摘要、类型、日期/状态、正文及可选封面/链接。
- 新增项目或文章自动进入栏目、搜索和适用分类；相关内容由ID关联，不复制全文。
- 草稿不进入公开列表、首页、搜索和公开计数。当前静态项目中的本地数据可见性不等同服务端权限。
- 首页精选是显式名单；文章“近期”按发布日期排序，编辑旧文章不自动变成新文章。
- 列表建议每页12项；不足一页隐藏分页。筛选与搜索保存在URL，返回列表恢复条件和滚动位置。
- 长标题、缺封面、空摘要、无外链、只有1项和没有内容都要有统一表现。
- 空筛选结果显示清除条件；无内容栏目显示简洁空态；首页空区块自动隐藏。
- 新增普通内容不改模板；新增前所未有的内容类型或交互能力，仍可能需要一次组件开发。

## 10. 定稿与实施顺序

本次是展示方案，当前代码不受影响。建议先评审这8种页面布局，再将接受的选择写成正式规范。

实施时先做一条完整链路“项目卡→项目详情”，再做文章与工具，最后首页精选与关于。每个模板用短标题、长标题、有图/无图、少量/大量内容验证；覆盖320、390、768、1024、1440px及浅深主题、键盘导航。

最终产出应是：已确认设计规范、共享组件、8种页面模板、内容字段/录入指南、组件示例页、必要的内容/路由/交互验证。样板内容用于验证版式，不作为用户经历自动发布。

## 11. 本轮建议确认的方向

首页精选项目采用“重点横卡 + 两张标准卡”；项目栏目采用两列封面卡；文章采用单列列表与专注阅读详情；工具采用紧凑分类卡与操作优先详情；关于采用个人介绍、近况和时间线。统一视觉基础，分别固定适合各类内容的展示模板。
